# บทที่ 1 บทนำ

## 1.1 ความเป็นมาและความสำคัญของปัญหา

กองบริหารงานกลาง สำนักงานมหาวิทยาลัย มหาวิทยาลัยเชียงใหม่ มีภารกิจหลักในการบริหารจัดการและกำกับดูแลทรัพย์สินประเภทครุภัณฑ์ (สังหาริมทรัพย์) เพื่อสนับสนุนการดำเนินงานของหน่วยงานภายในสำนักงานมหาวิทยาลัย ซึ่งครอบคลุมครุภัณฑ์หลากหลายประเภท เช่น ครุภัณฑ์คอมพิวเตอร์และเทคโนโลยีสารสนเทศ ครุภัณฑ์สำนักงาน ครุภัณฑ์ยานพาหนะและขนส่ง ครุภัณฑ์ไฟฟ้าและวิทยุ ตลอดจนครุภัณฑ์โสตทัศนูปกรณ์

ในอดีต กระบวนการบริหารจัดการ การบันทึกทะเบียนพัสดุ และการตรวจสอบสถานะครุภัณฑ์ยังคงดำเนินการผ่านแฟ้มเอกสารอิเล็กทรอนิกส์ในรูปแบบกระดาษคำนวณ (Spreadsheet / Microsoft Excel) เป็นหลัก ซึ่งส่งผลให้เกิดปัญหาและอุปสรรคสำคัญในการปฏิบัติงาน ได้แก่:

1. **การขาดระบบฐานข้อมูลกลางที่เป็นหนึ่งเดียว (Single Source of Truth):** ข้อมูลครุภัณฑ์กระจายอยู่ตามแฟ้มเอกสารของแต่ละงาน ทำให้การรวบรวมข้อมูลเพื่อสรุปภาพรวมขององค์กรต้องใช้เวลามากและมีความเสี่ยงต่อความซ้ำซ้อนหรือขัดแย้งของข้อมูล
2. **ความล่าช้าในการคำนวณอายุและค่าเสื่อมราคา:** เจ้าหน้าที่พัสดุต้องคำนวณอายุการใช้งานและประเมินค่าเสื่อมราคาด้วยตนเองตามรอบระยะเวลาการตรวจสอบประจำปี ซึ่งใช้เวลานานและอาจเกิดข้อผิดพลาดจากการคำนวณด้วยมือ
3. **การขาดการแจ้งเตือนเชิงรุก (Lack of Proactive Alerts):** ไม่มีระบบอัตโนมัติในการแจ้งเตือนครุภัณฑ์ที่ใกล้หมดอายุการใช้งาน (Warning) หรือเกินอายุการใช้งานตามเกณฑ์มาตรฐาน (Critical) ทำให้ไม่สามารถวางแผนการจำหน่ายพัสดุหรือจัดซื้อทดแทนได้อย่างทันท่วงที
4. **ข้อจำกัดในการวิเคราะห์ข้อมูลเชิงบริหาร (Executive Decision Support):** ผู้บริหารไม่สามารถเข้าถึงข้อมูลสถิติ สถานะความสมบูรณ์ มูลค่าราคาทุน และมูลค่าคงเหลือสุทธิของครุภัณฑ์แบบเรียลไทม์ ทำให้การจัดสรรงบประมาณซ่อมบำรุงและจัดซื้อใหม่ขาดข้อมูลสนับสนุนที่แม่นยำ
5. **ความเสี่ยงด้านความมั่นคงปลอดภัยของข้อมูล:** การแชร์ไฟล์กระดาษคำนวณไม่มีระบบควบคุมสิทธิ์การเข้าถึงอย่างรัดกุม ขาดการบันทึกประวัติการแก้ไข (Audit Trail) และเสี่ยงต่อการรั่วไหลของข้อมูลพัสดุของหน่วยงาน

ด้วยเหตุผลดังกล่าว จึงได้มีการริเริ่มและพัฒนาระบบ **SmartCAD-Inventory (ระบบบริหารจัดการครุภัณฑ์ กองบริหารงานกลาง สำนักงานมหาวิทยาลัย)** ขึ้นในรูปแบบเว็บแอปพลิเคชันสมัยใหม่ เพื่อยกระดับการบริหารจัดการทรัพย์สินให้มีประสิทธิภาพ รวดเร็ว ถูกต้อง แม่นยำ และมีความมั่นคงปลอดภัยตามมาตรฐานสากล

## 1.2 วัตถุประสงค์ของการวิจัยและพัฒนา

1. เพื่อออกแบบและพัฒนาระบบเว็บแอปพลิเคชันบริหารจัดการครุภัณฑ์สำหรับกองบริหารงานกลาง สำนักงานมหาวิทยาลัย มหาวิทยาลัยเชียงใหม่ ด้วยสถาปัตยกรรม Client-Side Rendering (CSR) และ Backend-as-a-Service (Supabase/PostgreSQL)
2. เพื่อพัฒนาระบบการประเมินอายุครุภัณฑ์อัจฉริยะ (Smart Age Evaluation Algorithm) พร้อมการคำนวณค่าเสื่อมราคาแบบเส้นตรง (Straight-Line Depreciation) อ้างอิงตามระเบียบและมาตรฐานของกรมบัญชีกลาง กระทรวงการคลัง
3. เพื่อพัฒนาระบบแดชบอร์ดสรุปผลเชิงภาพ (Data Visualization Dashboard) ที่แบ่งการแสดงผลออกเป็น 2 มุมมองหลัก ได้แก่ ภาพรวมทั่วไป (Overview) และการวิเคราะห์เชิงลึก (Deep Analytics) พร้อมฟังก์ชัน Drill-down เพื่อดูรายละเอียดรายชิ้น
4. เพื่อออกแบบและพัฒนาระบบรักษาความมั่นคงปลอดภัยสารสนเทศตามกรอบมาตรฐาน NIST Cybersecurity Framework โดยเน้นระบบควบคุมการเข้าถึงตามบทบาท (RBAC), Row-Level Security (RLS), การปิดระบบลงทะเบียนอิสระ (Closed Registration) และการจัดเก็บประวัติการทำงาน (Audit Logging)

## 1.3 ขอบเขตของโครงการ (Project Scope)

### 1.3.1 ขอบเขตด้านผู้ใช้งานและการควบคุมสิทธิ์ (User Roles & Access Control)
ระบบจัดแบ่งบทบาทผู้ใช้งานออกเป็น 4 ระดับ ตามหลักการ Role-Based Access Control (RBAC) ดังนี้:

| ระดับสิทธิ์ (Role) | สิทธิ์การเข้าถึงและการปฏิบัติงานในระบบ |
|---|---|
| **superadmin** (ผู้ดูแลระบบสูงสุด) | เข้าถึงทุกหน้าของระบบ, จัดการผู้ใช้งานทุกระดับ, กำหนดบทบาท, ดูแลฐานข้อมูล และตรวจสอบ Audit Log |
| **admin** (ผู้ดูแลระบบ) | จัดการผู้ใช้งาน (ระดับ staff/executive), นำเข้าข้อมูล (Upload Excel), ลบชุดข้อมูล, ดู Dashboard และออกรายงาน |
| **staff** (เจ้าหน้าที่) | ดูแดชบอร์ดภาพรวมและเชิงลึก, ค้นหาและดูทะเบียนครุภัณฑ์รายชิ้น (ไม่มีสิทธิ์อัปโหลดหรือแก้ไขข้อมูล) |
| **executive** (ผู้บริหาร) | ดูแดชบอร์ดภาพรวม แดชบอร์ดวิเคราะห์เชิงลึก และรายงานเชิงบริหาร (ไม่มีสิทธิ์อัปโหลดข้อมูล) |

*หมายเหตุ: ระบบปิดการลงทะเบียนสมัครสมาชิกด้วยตนเองอย่างเด็ดขาด (Closed Registration) โดยบัญชีผู้ใช้งานจะถูกสร้างผ่านระบบหลังบ้านโดยผู้ดูแลระบบเท่านั้น*

### 1.3.2 ขอบเขตด้านข้อมูล (Data Scope)
1. ข้อมูลครุภัณฑ์ที่นำเข้าสู่ระบบต้องเป็นไฟล์กระดาษคำนวณ (.xlsx, .xls) ตามโครงสร้างแบบฟอร์มทะเบียนพัสดุของกองบริหารงานกลาง
2. โครงสร้างข้อมูลประกอบด้วย: รหัสสินทรัพย์ (Asset ID), คีย์สินทรัพย์ (Asset Key), ชื่อครุภัณฑ์, รายละเอียด, ยี่ห้อ/รุ่น, ซีเรียลนัมเบอร์, วันที่ขึ้นทะเบียน, ราคาทุน, ระยะเวลารับประกัน, งาน/สังกัด, สภาพความพร้อมใช้งาน, ข้อมูลสถานที่ตั้ง (อาคาร, ชั้น, ห้อง), ผู้ครอบครอง และผู้ดูแล
3. ไฟล์เอกสารข้อมูลดิบ (.xlsx, .xls, .csv), ไฟล์สำรองฐานข้อมูล (.sql, .dump) และไฟล์บีบอัด (.zip) จะถูกกำหนดให้อยู่นอกระบบ Version Control (.gitignore) เพื่อความปลอดภัยของข้อมูล

### 1.3.3 ขอบเขตด้านเทคโนโลยีและสถาปัตยกรรม (Technical Scope)
1. **Frontend:** พัฒนาด้วยภาษา HTML5, CSS3 (CSS Custom Properties / Variables) และ Vanilla JavaScript (ES6+) แบบ Zero External UI Framework เพื่อประสิทธิภาพสูงสุด
2. **Backend & Database:** ใช้บริการ Supabase (PostgreSQL 15+) ในการจัดการฐานข้อมูล, ระบบพิสูจน์ตัวตน (Supabase Auth) และการรักษาความปลอดภัยระดับแถวข้อมูล (Row-Level Security: RLS)
3. **Data Visualization:** ใช้ไลบรารี Chart.js (v4.4.0) ร่วมกับ chartjs-plugin-datalabels (v2.2.0)
4. **Data Ingestion:** ใช้ไลบรารี SheetJS (XLSX v0.18.5) ประมวลผลและแปลงโครงสร้างข้อมูลบนฝั่ง Client
5. **Theme Support:** รองรับการแสดงผล 3 รูปแบบ ได้แก่ โหมดสว่าง (Light), โหมดมืด (Dark) และโหมดปรับตามระบบปฏิบัติการอัตโนมัติ (Auto)

## 1.4 ประโยชน์ที่คาดว่าจะได้รับ

1. **เพิ่มประสิทธิภาพและความรวดเร็วในการทำงาน:** ลดระยะเวลาในการค้นหา ตรวจสอบ และสรุปสถานะครุภัณฑ์ประจำปีจากเดิมที่ใช้เวลาหลายสัปดาห์ให้เหลือเพียงไม่กี่นาที
2. **สนับสนุนการวางแผนงบประมาณเชิงรุก:** ผู้บริหารและเจ้าหน้าที่สามารถทราบมูลค่าคงเหลือสุทธิและคาดการณ์ครุภัณฑ์ที่จะต้องจัดซื้อทดแทนล่วงหน้าได้อย่างแม่นยำ
3. **ลดข้อผิดพลาดและความซ้ำซ้อนของข้อมูล:** การจัดเก็บข้อมูลบนฐานข้อมูลแบบรวมศูนย์ช่วยลดปัญหาข้อมูลไม่ตรงกันระหว่างหน่วยงาน
4. **เพิ่มความโปร่งใสและตรวจสอบได้:** ระบบมีการบันทึกประวัติการทำรายการสำคัญ (Audit Log) ทุกครั้งที่มีการเข้าใช้งาน นำเข้าข้อมูล ลบข้อมูล หรือจัดการสิทธิ์ผู้ใช้
5. **สร้างมาตรฐานระบบต้นแบบ:** ได้สถาปัตยกรรมระบบบริหารจัดการสินทรัพย์ที่สามารถขยายผลและประยุกต์ใช้กับส่วนงานอื่น ๆ ภายในมหาวิทยาลัยเชียงใหม่ได้ในอนาคต

## 1.5 นิยามศัพท์เฉพาะ (Definition of Terms)

- **SmartCAD-Inventory:** ระบบเว็บแอปพลิเคชันบริหารจัดการครุภัณฑ์ กองบริหารงานกลาง สำนักงานมหาวิทยาลัย มหาวิทยาลัยเชียงใหม่
- **ครุภัณฑ์ (Asset/Inventory):** ทรัพย์สินที่มีลักษณะคงทนถาวร มีอายุการใช้งานตั้งแต่ 1 ปีขึ้นไป และมีมูลค่าตามเกณฑ์ที่ทางราชการกำหนด
- **ราคาทุน (Cost Price):** มูลค่าการจัดซื้อจัดหาครุภัณฑ์ ณ วันที่รับเข้าบัญชีทะเบียนพัสดุ
- **มูลค่าคงเหลือสุทธิ (Net Book Value):** มูลค่าของครุภัณฑ์หลังหักค่าเสื่อมราคาสะสมตามวิธีเส้นตรง (Straight-Line Depreciation)
- **Role-Based Access Control (RBAC):** กลไกการกำหนดสิทธิ์การเข้าถึงทรัพยากรของระบบตามบทบาทและหน้าที่ความรับผิดชอบของผู้ใช้งาน
- **Row-Level Security (RLS):** นโยบายความปลอดภัยระดับฐานข้อมูลของ PostgreSQL ที่จำกัดสิทธิ์การอ่าน เขียน หรือแก้ไขข้อมูลเฉพาะแถวที่ได้รับอนุญาต
